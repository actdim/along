# Glossary

_Domain terms for Along and repository tracking. Add or refine terms whenever introduced._

- **ALONG-PROTOCOL** - Provider-agnostic agent memory and project management standard enabling seamless pair-programming across Claude Code, Codex, OpenCode, and Antigravity via `.along/` and `AGENTS.md`.
- **Issue** - Discrete, structured unit of work (`feat`, `bug`, `debt`, `task`, `docs`, `spike`) tracked with YAML front-matter in `.along/ISSUES/` and summarized in `.along/ISSUES.md`.
- **Milestone** - Release target, stage, or sprint grouping multiple issues to measure delivery velocity and progress percentage in `.along/MILESTONES/`.
- **Risk / Blocker** - A technical blocker, missing credential, external dependency or security risk, tracked as an issue (usually `debt`) tagged `risk` with a `## Mitigation` section; the blocked issue names it in `blocked_by`. The separate `.along/RISKS/` entity was retired (ADR-2026-10-19--entity-model-slimmed).
- **Spike** - Timeboxed research, benchmark or PoC before an architectural decision: a `spike--<slug>` issue with an `## Outcome` section, closed as `done` when concluded. Replaced `.along/SPIKES/`.
- **Checklist** - The stage and session completion checklist in `AGENTS.md` / `docs/topic--along-protocol.md`, printed by `along wrap`. The scaffolded `.along/CHECKLISTS/` entity was retired; a project-specific checklist is a `docs/topic--<slug>.md` article.
- **Session Log** - Structured work session record in `.along/SESSIONS/<YYYY>/<YYYY-MM-DD>--<slug>.md`: summary, issues advanced/completed, ADRs, the attributed paths (`files:` front matter) and the blackboard record. It does not copy the plan or a file table.
- **Along installation** - A folder that owns Along state: a `.along/` with at least one state entry (`ISSUES`, `HISTORY.md`, `DECISIONS`, `.protocol-version`, ...), a legacy `.agents/` with state, or a declared root pointer. Created only by `along init`. An `AGENTS.md` alone, an empty `.along/` or one holding only Along side effects (scripts, artifacts, blackboards, diagnostics) is not one (ADR `along-installation-is-state-not-agents-md`).
- **Folder guide** - A nested `AGENTS.md` with instructions for working in that folder (progressive disclosure). Not a context: Along writes no protocol block into it, and its package `docs/` compile without a `.along/`.
- **Subproject** - A folder with its own Along installation: only a nested `.git` (repository, submodule, worktree) or a folder where the user ran `along init`. A package manifest alone is never one; a monorepo keeps one installation at its root (ADR `subproject-boundary-is-git-or-explicit-init`).
- **ADR (Architectural Decision Record)** - Append-only record of a non-trivial architectural or technical choice stored in `.along/DECISIONS.md`.
- **Knowledge Base (KB)** - Persistent project documentation repository in `.along/KB/` (`INDEX.md`, `01-architecture.md`, `02-domain-model.md`, `03-setup-and-workflow.md`).
- **Zero Friction** - Operational paradigm where agents automatically infer developer intent from natural conversation and manage project tracking entities in the background without human overhead.
- **Context Token Hygiene** - Practice of keeping root context files (`CONTEXT.md`, `ISSUES.md`, `AGENTS.md`) strictly compact (< 50-80 lines) to prevent LLM context bloat while pushing details into session logs and KB articles.
- **FULL / REF protocol block** - The managed `ALONG-PROTOCOL` block in `AGENTS.md`: FULL (whole protocol) at an architecture root or git repository/submodule root; REF (short pointer, `ref=<relpath>`) in a nested folder whose ancestor in the same git working tree carries the FULL block.
- **Protocol reference** - The managed on-demand article `docs/topic--along-protocol.md`, rendered from `skills/along-init/protocol-reference.md` by `along init` / `along update` at FULL roots. Holds the full rule wording and situational procedure that the slim `AGENTS.md` core points to.
- **Profile section** - A `<!-- profile: light -->` / `<!-- profile: !light -->` ... `<!-- /profile -->` span in a protocol source, kept only for the matching gate strictness profile and stripped on render.
- **Imported VISION section** - A root `VISION.md` merged into `.along/VISION.md` between `<!-- along:imported-vision needs-restructure ... -->` markers when both had content; the agent decomposes it and removes the markers, `along doctor` reports it until then.
- **Along context** - A directory the runtime hooks govern: it owns a `.along/` holding Along state (not just hook `diagnostics/`), a legacy `.agents/` with Along entities, or a declared root. A bare `AGENTS.md` is not one.
- **Declared root** - An Along context whose state lives in another directory, declared by `<!-- along-root: <relpath> -->` in its `AGENTS.md` or by `context_roots` in `~/.along/config.json`; `repo.state_dir` resolves to `<relpath>/.along/`.
- **Root notes** - Root-level `ROADMAP.md`, `ARCHITECTURE.md`, `SPEC.md`, `TODO.md`, `DESIGN.md` that duplicate the Knowledge Base; listed by `along init`, migration, `along doctor` and `along kb-sync`, routed by the agent.
- **Blackboard Record** - The `## Blackboard Record` section of a session log: step table, research, execution trace, notes and reviews of an issue's blackboard (logs before v4.6.0 also copied the plan and an attributed files table), written by `along wrap`, `along scratch purge` or `along issue done` before the blackboard is deleted; append-only once committed (`session_record_append_only`).
- **Execution trace** - `.along/.session/<slug>/execution_trace.md`: edits, test runs with results, gate denials, approvals, phase and step changes of the issue a session is bound to, written by the hooks and Along commands in direct and role-based mode.
- **Completion token** - Entry `completed: [{slug, approved_at, wrapped_at}]` that `along wrap` leaves in the binding of the session whose plan for the slug was approved; lets that session's `along commit -i <slug>` pass the plan gate once.
- **Session event ledger** - `.along/.session/<slug>/events.jsonl`: one versioned record `{schema, ts, session, slug, kind, path, path_kind, ok}` per edit, test run, plan and approval of the issue a session is bound to; source of truth for attribution and closeout, projected onto telemetry (ADR-2026-10-05--session-event-ledger-feeds-telemetry).
- **Attribution** - Which issue a changed file belongs to, from the session event ledger; a file attributed to several issues is shared, a change no ledger records is unattributed and never committed by a closeout.
- **Closeout** - `along session close`: tests once, wraps every ready issue, commits by attribution (one commit per issue, combined commits for shared files, projections last), pushes once; resumable from `.along/.session/.closeout.json`.
- **Closeout approval** - `closeout: {slugs, approved_at}` in a session binding, recorded by `along plan approve --closeout` after the user's yes; lets that session close out and commit those issues.
- **Orphan blackboard** - A blackboard no session is bound to whose issue is closed or missing; reported by `along doctor`, archived and removed by `along scratch purge`.
- **Context chain** - The enclosing `.along/` contexts from the nearest up to the outermost below home (`repo.context_chain`), crossing nested `.git` boundaries; entity references resolve along it (ADR-2026-10-11--gate-friction-fixes).
- **Gate tier** - `invariant` (always enforced, never shadowed, disabled or bypassed), `process` (enforced by default, bypassable with a recorded reason) or `advisory` (warn only); `hooks.config.GATE_TIERS`.
- **Bypass** - Skipping a process gate with `-n` / `--force-reason` / `scratch fallback`: needs `--reason` and, where user messages are recorded, the user's reply after the gate failed; written to the trace, `hooks_audit.jsonl` and an `Along-Bypass:` commit trailer.
- **Verify policy** - `.along/config.json` `verify`: `tests: required` (tests must run) or `tests: none` with `reason`, `tracked_by` and replacement `checks`.
