# arXiv Academic Research Paper: Git-Native Agent Context Architecture

## Problem

Publishing on arXiv (specifically in `cs.SE` - Software Engineering or `cs.AI` - Artificial Intelligence) requires strict adherence to academic standards:
1. **Academic Rejection Risk**: Unstructured whitepapers, promotional documentation, and product user manuals are routinely rejected by arXiv moderators as lacking research rigor.
2. **Missing Formalization**: Along's architectural principles (Dual-Tier State & Provenance, Mechanical Runtime Gates, Zero-Vector retrieval) need formal mathematical and systems formulation.
3. **Empirical Evidence**: The paper must present rigorous benchmark results with statistical significance tests (p < 0.01) comparing Along against conversational history accumulation.

### 2. Paper Section Structure

- **Title**: *"Git-Native Agent Context Architecture: Decoupling Ephemeral Execution from Auditable Repository Memory with Zero-Vector Retrieval"*.
- **Abstract**: Concise problem statement, proposed Dual-Tier model, and summary of empirical findings.

- **Section 1: Introduction**:
  - Context window economics and the O(T^2) cost of append-only conversational history.
  - The insufficient solution of naive state-wiping (SKILL.state) that destroys engineering provenance.
  - Contributions summary: Dual-Tier State & Provenance, Zero-Vector Retrieval, Mechanical Runtime Gates, and empirical evaluation on public benchmarks.

- **Section 2: Related Work & Limitations of Conversational Execution**:
  - 2.1 Conversational Agent Runtimes: ReAct (Yao et al., 2022), LangGraph, AutoGen (Wu et al., 2023).
  - 2.2 Memory Architectures: MemGPT (Packer et al., 2023), Mem0 (Chhikara et al., 2025), episodic retrieval (Park et al., 2023).
  - 2.3 Explicit State Transition Models: SKILL.state (Badhe et al., 2026), Dialogue State Tracking (Williams et al., 2013; Rastogi et al., 2020).
  - 2.4 Context Compression: LLMLingua (Jiang et al., 2023), Attention Sinks (Xiao et al., 2024).
  - 2.5 Vector Retrieval in Code: Code search via embeddings, limitations of blind token chunking across AST boundaries.

- **Section 3: The Along Architecture**:
  - 3.1 Dual-Tier State & Provenance:
    - Operational Tier: Formal definition of clean-turn execution. At step t, worker receives only (P, Sigma_t, O_t^distilled). Intermediate reasoning R_t is discarded from operational context after state patch validation but preserved asynchronously in provenance tier.
    - Provenance Tier: Git-grounded session logs (`.along/SESSIONS/`), modular ADRs (`.along/DECISIONS/`), issue DAG (`.along/ISSUES/`). All artifacts versioned, diffable, and auditable.
    - Formal complexity: Operational prompt footprint O(1), cumulative tokens O(T), provenance storage O(T) on disk (not in prompt).
  - 3.2 Zero-Vector Retrieval:
    - Smoothed TF-IDF with word-boundary tokenization over Markdown and YAML front-matter.
    - Bounded snippet extraction (< 150 tokens, < 50 ms).
    - No native C++/CUDA dependencies, no background daemons, no vector database.
    - Formal comparison with chunked embedding retrieval: preservation of AST boundaries, Git-branch awareness.
  - 3.3 Observation Distillation:
    - Filtering background telemetry and verbose passing output before injection into agent context.
    - Structured error isolation: extracting failing test assertions and stack traces while discarding platform chatter.
  - 3.4 Mechanical Runtime Gates:
    - Sub-millisecond (< 1 ms) deterministic interceptors vs. probabilistic LLM-based guardrails (300 ms - 4,000 ms).
    - Declarative YAML gate engine with bi-directional traceability.

- **Section 4: Empirical Evaluation**:
  Integrates all results from `feat--empirical-benchmark-harness-and-metrics`, organized by evaluation track:

  - 4.1 Evaluation on SWE-bench Verified (Track A1):
    - **Datasets**: 25-30 task subset from SWE-bench Verified spanning `django`, `sympy`, `pytest`, `scikit-learn`, `flask`.
    - **Baselines**: ReAct, Summarization, Stateful (LangGraph), Along Dual-Tier.
    - **Primary Metric**: pass@1 (binary success rate).
    - **Secondary Metrics**: Cumulative tokens per task, average prompt size.
    - **Expected Finding**: Along achieves comparable or higher pass@1 while consuming 40-60% fewer cumulative tokens.

  - 4.2 Retrieval Quality on RepoBench (Track A2):
    - **Dataset**: RepoBench cross-file code completion tasks.
    - **Systems**: Along Zero-Vector (TF-IDF), ChromaDB (all-MiniLM-L6-v2), BM25.
    - **Metrics**: Recall@1, Recall@3, Recall@5, Retrieved Token Count, Retrieval Latency (ms).
    - **Expected Finding**: Along Zero-Vector achieves competitive Recall with 3-5x fewer retrieved tokens and 5-10x faster latency than ChromaDB, with zero native extension dependencies.

  - 4.3 Interactive Terminal Execution on InterCode CTF (Track A3):
    - **Dataset**: 30-50 InterCode Bash/CTF challenges.
    - **Metric**: pass@1 (exact flag match).
    - **Expected Finding**: Along's hypothesis tracking in structured state prevents command repetition, improving pass rate.

  - 4.4 Long-Horizon Token Scaling (Track B1):
    - **Setup**: Sequential engineering tasks on `psf/requests`, horizons T in {10, 25, 50, 100}.
    - **Metrics**: Cumulative input tokens at each step (scaling curve), task accuracy.
    - **Expected Finding**: Along maintains flat prompt size and linear cumulative tokens; ReAct and Stateful exhibit quadratic growth.
    - **Statistical Rigor**: 5 seeds, mean +/- std dev, paired t-test p < 0.01 at T >= 50.

  - 4.5 Noise Robustness (Track B2):
    - **Setup**: T=50, distractor rates: 0, 5, 20, 50 events/turn.
    - **Expected Finding**: Along maintains >= 0.95 accuracy across all noise levels; ReAct degrades from ~0.68 to ~0.53.

  - 4.6 State Recovery Under External Drift (Track B3):
    - **Setup**: External file modification at step T/2.
    - **Metric**: Recovery lag (consecutive incorrect turns).
    - **Expected Finding**: Along recovers in 0 steps; history-based baselines require 5-8 turns.

- **Section 5: Discussion & Limitations**:
  - Trade-offs: deterministic gates cannot catch novel semantic violations.
  - Schema authoring overhead: structured state schemas require upfront design per domain.
  - Open-model fragility: smaller models (< 30B params) show higher structured output error rates.
  - Provenance storage cost: session logs grow linearly on disk (negligible compared to Git repository size).

- **Section 6: Conclusion**:
  - Summary: Git-native dual-tier architecture achieves bounded token scaling while preserving full engineering audit trail.
  - Open-source availability: GitHub repository link and installation instructions.
