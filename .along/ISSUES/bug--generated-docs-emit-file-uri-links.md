# Generators emit file:// links that the protocol forbids and that render dead everywhere

## Problem

The repository contains 116 `](file://...)` links across 12 files, and the generators
produce them:

```python
# scripts/along_kb_sync.py:610-613  (docs/INDEX.md generator)
index_body_lines.append("- [AGENTS.md](file://AGENTS.md): Active protocol conventions and rules.")
index_body_lines.append("- [.along/DECISIONS.md](file://.along/DECISIONS.md): Architectural Decision Records.")
index_body_lines.append("- [.along/ISSUES.md](file://.along/ISSUES.md): Active issue tracking board.")
index_body_lines.append("- [.along/HISTORY.md](file://.along/HISTORY.md): Append-only project history log.")
```

Distribution of the 116 occurrences:

```text
.along/ISSUES.md                  40   (generated by issue sync)
.along/HISTORY.md                 34   (appended by wrap)
.along/DASHBOARD.md               12   (generated by dash)
rules/INDEX.md                    11
docs/topic--frontend-frameworks.md 5
docs/INDEX.md                      4   (generated by kb-sync)
AGENTS.md                          1
plus 5 more files
```

## The contradiction

Two governing documents state opposite rules:

- `skills/along-kb-sync/SKILL.md:23` - "Never use absolute URLs, local filesystem schemes
  (`file:///`), or OS-specific backslashes."
- `AGENTS.md` (Technical Markdown Standards) - "Relative & Portable Links: Always use
  relative paths (`file://...` or standard markdown links)".

The `AGENTS.md` formulation is itself incoherent: `file://` is not a relative path. Since
`AGENTS.md` is the always-loaded instruction file, agents follow the wrong half of the
contradiction, which is how 116 of these accumulated.

## Why it matters concretely

`file://` links do not resolve for a reader on GitHub, GitLab, GitHub Pages, npm, NuGet,
PyPI, or crates.io. Meanwhile `skills/along-kb-sync/SKILL.md:24` promises:

```text
Cross-Platform Renderers: Guarantees 100% clean rendering across GitHub, GitLab,
GitHub Pages (Jekyll, Astro, Docusaurus, MkDocs), npm, NuGet, PyPI, and crates.io.
```

The generated `docs/INDEX.md`, which is the documented public entry point of the Knowledge
Base, has four dead links in its "Related Context" section. The integrity gate passes them
because it resolves `file://` against the filesystem with bespoke logic
(`along_kb_sync.py:437-448`) instead of flagging the scheme.

## Requirements

- REQ-1: Resolve the rule conflict in favor of standard relative markdown links, and record
  an ADR. Update `AGENTS.md`, `skills/along-init/protocol.md`, and every skill that repeats
  the rule.
- REQ-2: Fix all generators to emit relative links computed from the file being written:
  - `along_kb_sync.py` INDEX generator;
  - the `issue sync` projection generator in `along_exec.py`;
  - the HISTORY line format in `along-wrap` / history sync;
  - the dashboard markdown export.
- REQ-3: Add a one-time migration that rewrites the existing 116 links to relative form,
  covering `.along/**` (which requires `[bug--link-gates-skip-along-directory]` first).
- REQ-4: Make the integrity gate treat `file://` as a violation rather than resolving it, so
  the rule is enforced by code and cannot regress.
- REQ-5: Remove the Windows drive-letter resolution branch once the scheme is banned.
- REQ-6: Verify the "universal rendering" claim honestly: either keep it and enforce it by
  test, or soften the wording.
- REQ-7: Tests: generators produce no `file://`; gate fails on a `file://` link; migration
  converts a fixture correctly including anchors.

## Acceptance Criteria

- [ ] Zero `](file://` occurrences in the repository.
- [ ] Generators emit relative links only, enforced by test.
- [ ] Integrity gate flags `file://` as a violation.
- [ ] Rule stated identically in `AGENTS.md`, `protocol.md`, and all skills.
- [ ] ADR recorded.
