## Context
The ticket says what and why (problems A and B, analysis of the proposals, REQ-1..6). In short:
the test gate demands tests after edits that cannot affect them (editor / agent configs), and
the protocol has no rule for failures the active issue did not cause, so agents "fix" unrelated
code and edit tests to get green. Proposal 3 of the report (classify failures by diff paths) is
replaced by a recorded HEAD baseline.

## Steps
1. **Classifier** (`scripts/alongkit/verify.py`) - one notion of "test-inert path":
   - `TEST_INERT_GLOBS`: `.vscode/**`, `.idea/**`, `*.code-workspace`, `.editorconfig`,
     `.claude/**`, `.codex/**`, `.cursor/**`.
   - `test_gate_option(repo_root, key)`: reads an option of `test_before_stop` from
     `.along/rules/gates.yaml`; the loop moves here from `gates.get_doc_tests`, which then calls it.
   - `test_inert_globs(repo_root)`: built-ins plus `ignore_paths`.
   - `is_test_inert_path(rel, globs)`: fnmatch with `/**` handled like `predicates._matches_pattern`.
   - `docs_only_change`: an inert path counts like documentation (a commit of only inert paths skips tests).
2. **Stop gate** (`scripts/alongkit/hooks/predicates.py`):
   - Edit tracking (around line 430): an inert path neither arms the gate nor counts as a doc
     edit; it still goes to the ledger and trace.
   - `edited_files` is reset when a test run is recorded; `check_test_before_stop` names up
     to 5 of them in the message.
3. **Tree hash and baseline** (`scripts/alongkit/testruns.py`):
   - `tree_hash` also excludes `test_inert_globs(repo_root)` as `:(glob)` pathspecs.
   - `head_tree_hash(repo_root)`: HEAD's tree with the same exclusions (throwaway index,
     `read-tree HEAD`, no `add -A`); equals `tree_hash` on a clean tree.
   - `baseline_note(repo_root)`: from the last recorded run on `head_tree_hash` - red: "already
     failing at HEAD (<ts>): pre-existing; report and file an issue, do not fix under this
     issue, bypass only after the user's reply"; green: "green at HEAD (<ts>): the failures
     come from the working-tree changes"; none: the rule without a verdict.
4. **Record red runs**: `.along/scripts/test.py` records a full-suite run green or red and
   prints `baseline_note` on failure; `gates.run_test_gate` prints it on `TESTS_FAILED`
   (covers commit, wrap, closeout, bump).
5. **Protocol core** (`skills/along-init/protocol.md`, budget 6144 B, 5513 B used):
   - Gate line: "before stopping: tests run after your last edit, session wrapped, projections synced."
   - New judgment rule: "Stay in scope: failures your issue did not cause (red at HEAD,
     untouched code) are reported and filed as an issue, never fixed under this one; never
     edit tests or fixtures to make them pass unless the issue is about them; bypass
     (`-n --reason`) only after the user's reply."
   - Refresh the `AGENTS.md` managed block with the along-init refresh, not by hand.
6. **Procedure** (`skills/along-init/protocol-reference.md`, both profiles): checklist item 1
   becomes "Zero failures caused by this issue", plus the pre-existing failure procedure with
   `along commit -n --reason "pre-existing failure in <suite>, tracked in <key>"` and the same
   for `along wrap`. `docs/topic--along-protocol.md` is regenerated by the same refresh.
7. **Docs**: `docs/topic--runtime-hooks-and-gates.md` (Activity trace, Test reuse),
   `docs/topic--declarative-gates-and-traceability.md` (item 8, options example), a comment on
   `ignore_paths` in `scripts/alongkit/hooks/default_gates.yaml`.
8. **Tests** (existing test files of the trace, verify and testruns):
   - `.vscode/settings.json` and `.claude/settings.local.json` edits do not arm the gate;
     `package.json` does; an `ignore_paths` match does not; the message names the files.
   - `docs_only_change` is true for inert-only changes.
   - `head_tree_hash == tree_hash` on a clean repo; an inert file does not change `tree_hash`.
   - `baseline_note` for red, green and missing HEAD runs; `run_test_gate` prints it on failure.
   - Budgets: `protocol.md` <= 6 KB, `AGENTS.md` core <= 7 KB.

- `along test` (`lifecycle.run_lifecycle_command`, `lifecycle.py:208-236`) already records

  repositories need no change to their scaffolded `test.py`.
- `doc-manual-lock` (`predicates.check_doc_manual_lock`) checks file-tool edits only. `along

  and needs no `docs--` issue. Never edit either file with file tools.
- There is no `along init --refresh`; the refresh is `along init` with the other pipeline

## Steps
1. **Classifier** (`scripts/alongkit/verify.py`):
   - `TEST_INERT_GLOBS = (".vscode/**", ".idea/**", "*.code-workspace", ".editorconfig",
     ".claude/**", ".codex/**", ".cursor/**")`. Patterns are repo-relative; a bare name such as
     `*.code-workspace` or `.editorconfig` also matches in any subfolder (match against the
     basename when the pattern has no `/`).
   - `test_gate_option(repo_root, key, default=None)`: reads `key` of the `test_before_stop`
     entry from `.along/rules/gates.yaml` (ruamel safe load via `bootstrap.require`); returns
     `default` on a missing file, parse error or wrong type. Move the loop out of
     `gates.get_doc_tests`; `get_doc_tests` calls the helper and keeps its default list.
   - `test_inert_globs(repo_root) -> List[str]`: built-ins plus `ignore_paths` (only a list of
     non-empty strings; anything else is ignored with no error).
   - `is_test_inert_path(rel, globs) -> bool`: posix-normalized, `./` stripped, fnmatch;
     `dir/**` also matches `dir` and everything below it (same rule as
     `predicates._matches_pattern`).
   - `docs_only_change(repo_root, paths, diff_for)`: a path for which `is_test_inert_path`
     holds counts like a doc path. A commit of only inert paths prints the existing
     "tests skipped" note.
2. **Stop gate** (`scripts/alongkit/hooks/predicates.py`):
   - Edit tracking (the `if rel and is_source_edit(rel)` branch, around line 430): first test
     `verify.is_test_inert_path(rel, verify.test_inert_globs(repo_root))`; an inert path
     updates neither `last_edit_time` nor `last_doc_edit_time`. Ledger and trace entries above
     it stay as they are.
   - Test-run tracking (the branch that sets `last_test_time`, around line 452): also set
     `trace["edited_files"] = []` for a full (non `--doc`) run, so the list holds only edits
     since the last run.
   - `check_test_before_stop`: the source-edit message names up to 5 entries of
     `edited_files` ("Source files were modified in this session (a, b, +N more), ...").
3. **Tree hash and HEAD baseline** (`scripts/alongkit/testruns.py`):
   - `tree_hash(repo_root)`: after the existing `rm --cached` of `EXCLUDED_PATHSPECS`, also
     remove `[":(glob)" + g for g in verify.test_inert_globs(repo_root)]` (bare-name globs as
     `:(glob)**/<name>`). Import `verify` lazily inside the function to avoid a cycle.
   - `head_tree_hash(repo_root) -> Optional[str]`: same throwaway-index technique: `read-tree
     HEAD`, the same `rm --cached` list, but keep `.along/scripts/**` from HEAD (re-add is not
     needed: remove with `:(glob)**/.along/**` plus `:(exclude,glob)**/.along/scripts/**`),
     `write-tree`. None outside git or when HEAD does not exist (repo with no commits).
   - `baseline_note(repo_root) -> str`: the last run in `load_runs` whose `tree_hash` equals
     `head_tree_hash`:
     - red: "[Baseline] The suite already failed at HEAD (<ts>, <source>): failures in code this
       issue did not touch are pre-existing. Report them to the user and file an issue; do not
       fix them under this issue; bypass (-n --reason) only after the user's reply."
     - green: "[Baseline] The suite passed at HEAD (<ts>, <source>): the failures come from the
       working-tree changes."
     - none (no record, no HEAD): "[Baseline] No recorded run at HEAD. If the failures are in
       code this issue did not touch, report them before changing anything; never edit tests
       to make them pass. Tip: run 'along test' on a clean tree before editing to get a baseline."
4. **Print the baseline on failure** (no new recording is needed except in 4c):
   a. `lifecycle.run_lifecycle_command`: after `record_run`, when `action == "test"` and
      `code != 0` (and not `NO_TESTS_EXIT_CODE`), print `testruns.baseline_note(repo_root)`.
      Covers `along test` in every repository.
   b. `gates.run_test_gate`: print it in the `TESTS_FAILED` branch (not for misconfiguration or
      no tests). Covers commit, wrap, closeout, bump.
   c. `.along/scripts/test.py` (this repository's hook, run directly): record a full-suite run
      when red too (`record_run(..., result.wasSuccessful(), tree, "test.py")`, still not for
      `--doc` or a subset), and print the note when red.
5. **Protocol core** (`skills/along-init/protocol.md`, budget 6144 B, 5513 B used):
   - Gate line 37: "before stopping: tests run after your last edit, session wrapped,
     projections synced."
   - New judgment rule after the "Never delete or truncate" line, outside the profile blocks:
     "- Stay in scope: failures your issue did not cause (red at HEAD, untouched code) are
     reported and filed as an issue, never fixed under this one; never edit tests or fixtures
     to make them pass unless the issue is about them; bypass (`-n --reason`) only after the
     user's reply."
   - Check the size (`test_context_budget`); trim wording, not other rules, if over.
6. **Procedure** (`skills/along-init/protocol-reference.md`, checklist item 1 in both profile
   variants, lines 104 and 115): "Run via `/along-test` with quiet flags. Zero failures caused
   by this issue. On a failure the test gate prints a `[Baseline]` line. Pre-existing failures
   (red at HEAD, code the issue did not touch): halt, report the exact failures to the user,
   file an issue, and only with their agreement bypass: `along commit -n --reason
   "pre-existing failure in <suite>, tracked in <key>"`, `along wrap <slug> -n --reason "..."`.
   Never edit tests or fixtures to make them pass unless the issue is about them." Same size
   check for the rendered doc if a budget test covers it.
7. **Refresh generated files**: `along init . --dry-run --no-rules --no-git --no-hooks
   --no-migrate`, confirm the report lists only the `AGENTS.md` managed block and
   `docs/topic--along-protocol.md`, then run it without `--dry-run`. If it lists anything
   else, stop and report to the user. `llms.txt` / `llms-full.txt` follow via `/along-kb-sync`
   if they embed the protocol.
8. **Docs** (`write_policy` not manual; check before editing):
   - `docs/topic--runtime-hooks-and-gates.md`: Activity trace (inert paths, `ignore_paths`,
     file list in the message), Test reuse (inert paths left out of the hash, HEAD baseline).
   - `docs/topic--declarative-gates-and-traceability.md`: item 8 and the options example
     (`ignore_paths`).
   - `scripts/alongkit/hooks/default_gates.yaml`: a comment on `ignore_paths` at

9. **Tests** (in the existing files):
