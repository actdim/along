# A 205 KB generated dashboard is committed, churns history, and has no merge strategy

## Problem

```text
.along/dashboard.html   204,897 bytes   tracked in git
.along/DASHBOARD.md       3,247 bytes   tracked in git
```

`.along/dashboard.html` appears in 18 of 109 commits. It is regenerated by
`along_dash.py --cli`, which the test suite invokes against the live repository
(`tests/test_skills_and_scripts.py:173-185`), so a plain `python -m unittest discover tests`
dirties it; and `along_commit.py` runs the suite before every commit, then stages everything
with `git add -A`. The artifact is therefore committed as a side effect of committing
anything else.

## Contradiction with the protocol's own model

`AGENTS.md` defines the concurrency model:

> SSOT Entities: atomic markdown files ...
> Derived Projections (Compiled Views): `.along/ISSUES.md`, `docs/INDEX.md`, `.along/DASHBOARD.md`.
> Zero-Manual-Merge Rule: when git merge conflicts occur in derived projections
> (`ISSUES.md`, `INDEX.md`), never resolve diffs manually ... recompile.

Three inconsistencies follow:

1. `DASHBOARD.md` is listed as a derived projection, yet it is committed, and
   `dashboard.html` is not listed at all despite being the largest derived artifact.
2. The Zero-Manual-Merge Rule names only `ISSUES.md` and `INDEX.md`. There is no recompile
   instruction for `DASHBOARD.md` / `dashboard.html`, so a parallel-branch conflict in a
   205 KB single-line-heavy HTML file has no defined resolution.
3. `.gitattributes` declares `merge=union` only for `HISTORY.md` and `DECISIONS.md`. A
   conflict in `dashboard.html` will be a raw textual conflict in generated markup.

## Impact

Repository size and diff noise grow for zero informational value, every parallel branch is a
potential unresolvable conflict, and `git status` is never clean after running tests. It also
undermines the SSOT/projection distinction that the protocol presents as an architectural
strength.

## Requirements

- REQ-1: Decide the artifact policy and record it as an ADR. Recommended: generated views
  are not tracked. Add `.along/dashboard.html` (and, if agreed, `.along/DASHBOARD.md`) to
  `.gitignore` and remove them from tracking.
- REQ-2: If a committed snapshot is genuinely wanted (for example for GitHub Pages), move it
  to an explicit export path (`docs/dashboard.html`), generate it only on an explicit
  `--export`, and never as a side effect of tests or commits.
- REQ-3: Extend the Zero-Manual-Merge Rule to name every derived projection, and add
  `merge=ours` (or a recompile-on-conflict note) in `.gitattributes` for tracked projections.
- REQ-4: Stop generating artifacts from the test suite
  (`[bug--tests-mutate-working-tree]` REQ-1).
- REQ-5: Add a test asserting that no file listed as a derived projection is tracked, unless
  it appears in an explicit allowlist with a documented reason.

## Acceptance Criteria

- [ ] Generated dashboard artifacts untracked, or exported explicitly to a documented path.
- [ ] Every derived projection named in the Zero-Manual-Merge Rule with a defined strategy.
- [ ] Test suite no longer regenerates tracked artifacts.
- [ ] Guard test in place.
- [ ] ADR recorded.
