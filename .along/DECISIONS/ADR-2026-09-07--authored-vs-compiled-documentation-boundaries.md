# ADR-2026-09-07--authored-vs-compiled-documentation-boundaries - Authored vs Compiled Documentation Boundaries and Automated Consistency Gates

- Date: 2026-09-07
- Status: accepted
- Context:
  1. The Along protocol, skill definitions, and architecture reference were duplicated across 5 distinct documentation surfaces (`AGENTS.md`, `skills/along-init/protocol.md`, `docs/topic--skills-reference.md`, `llms.txt` / `llms-full.txt`, and `README.md`).
  2. Over time, without strict single sources of truth (SSOT) and automated consistency gates, the surfaces drifted: deleted skills (e.g. `along-context-sync`) remained advertised in `AGENTS.md`, outdated `protocol_version` strings persisted in `docs/topic--*.md`, and phantom paths were referenced.
  3. A clear architectural boundary was required to define which files are authored human/agent sources and which are deterministically compiled projections.
- Decision:
  1. **Core Protocol SSOT**: `skills/along-init/protocol.md` is the canonical Single Source of Truth for the ALONG-PROTOCOL text. The managed block in `AGENTS.md` is a compiled projection demarcated by `<!-- BEGIN ALONG-PROTOCOL ... -->` and `<!-- END ALONG-PROTOCOL -->`, generated by `along-init` / `along-update` and verified by automated regression test `test_03b`.
  2. **Skills Catalog SSOT**: The `skills/along-*/SKILL.md` manifests are the SSOTs for individual skills. Documentation summaries in `README.md`, `AGENTS.md` (Project specifics), and `docs/topic--skills-reference.md` are verified 1:1 against the filesystem by `test_04b_skill_catalog_consistency`.
  3. **Compiled Knowledge Base Projections**: `docs/INDEX.md`, `llms.txt`, and `llms-full.txt` are deterministically compiled projections generated by `along_kb_sync.py` from active `docs/topic--*.md` articles and repository entry points. They must never be manually maintained.
  4. **Active Protocol Version Reconciliation**: `docs/topic--*.md` articles represent living system documentation. `along_kb_sync.py` automatically reconciles each article's `protocol_version` front-matter to `CURRENT_PROTOCOL_VERSION`, and `test_04d` prevents version drift.
  5. **Path Verifiability Gate**: All filesystem paths referenced in documentation must exist on disk, verified by `test_04c`.
- Consequences:
  - Eliminates silent documentation drift across all protocol and skill entry points.
  - Guarantees 1:1 correspondence between installed skills and documented skills.
  - Automated tests fail immediately if a deleted skill or outdated path remains in documentation.
