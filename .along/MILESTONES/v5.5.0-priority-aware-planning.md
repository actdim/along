# Milestone: v5.5.0 Priority-Aware Planning & Deterministic Sequencing

## Intent

A single `priority` field mixes three different questions: **value** (who needs it and how much - only a human knows), **sequencing** (what is cheaper to build first - derivable from dependencies), and **risk / effort** (estimated by the agent, confirmed by a human). Milestone `v5.5.0` separates these axes, makes the planning strategy an explicit, recorded choice, and turns ordering mistakes into deterministic gate failures instead of relying on agent judgment.

## Target Scope & Core Issues

1. `[feat--planning-fields-and-ordering-gates]`:
   - Coarse planning fields on issues (`requested_by`, `value`, `effort`, `risk`, `deferred_reason`) and `planning_strategy` on milestones / repo config.
   - Ordering gates: issue scheduled before its blocker, `blocked_by` cycles, missing strategy, deferred high-value customer requests without rationale.

2. `[feat--along-plan-strategies]`:
   - Built-in strategies (`value-first`, `foundation-first`, `risk-first`, `quick-wins`, `deadline-driven`, `cost-of-delay`) as deterministic sort keys.
   - `along plan <milestone>` proposes an order and milestone assignment with explanations; the human approves.

## Definition of Done for v5.5.0

- [ ] All target issues implemented, tested with hermetic test suites, and marked done.
- [ ] Ordering gates run in `along doctor --entities` and CI with zero false positives on this repository.
- [ ] Planning strategies documented in `docs/topic--domain-model.md` and `docs/topic--cli-reference.md`.
